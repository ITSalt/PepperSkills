# `pepper-ru-web-compliance`

Скилл проверяет сайт на соответствие требованиям российского законодательства и
выдаёт два документа: аналитическую записку для владельца и юриста и план
правок для агента-разработчика.

Проверка чёрного ящика: скилл открывает сайт как обычный посетитель, смотрит
разметку, сетевые запросы, cookie и правовые документы. Доступ к исходникам не
нужен, но если он есть — план получает точные файлы вместо селекторов.

## Какую проблему решает

Владелец сайта обычно знает, что «что-то надо про персональные данные», и не
знает, что именно. Юрист знает нормы, но не открывает DevTools и не читает
сетевой лог. Разработчик читает лог, но не знает, что ч. 4 ст. 9 ФЗ-152 требует
активной ссылки в подписи чекбокса.

В результате сайт живёт с нарушениями, за которые с 2025 года штрафуют заметно
дороже прежнего: до 700 тыс. ₽ за форму без согласия, до 6 млн ₽ за
неуведомление об утечке, с 07.07.2026 — до 700 тыс. ₽ за вход через
иностранного провайдера.

Скилл закрывает разрыв: механическую часть делает скрипт, смысловую —
модель, а на выходе документ, который можно отдать и юристу, и разработчику.

## Что внутри

44 правила, сгруппированных по предмету:

| Группа | Правил | О чём |
|--------|--------|-------|
| Авторизация | 8 | п. 10 ст. 8 ФЗ-149, ст. 13.55 КоАП: вход через Google, Apple, Telegram, иностранные IDaaS |
| Дисклеймеры и символика | 9 | плашки иноагентов (ПП РФ № 2108), экстремистские и нежелательные организации, символика Meta |
| Персональные данные | 13 | 152-ФЗ: политика, согласия, трансграничная передача, локализация базы, уведомление РКН |
| Cookie и трекеры | 7 | баннер согласия, загрузка трекеров до согласия, юрисдикция получателей |
| Инфраструктура | 4 | HTTPS, хостинг, география приёмников данных форм |
| Реквизиты | 3 | ЗоЗПП и ст. 22.1 ФЗ-152 |

По типу проверки: 22 правила закрывает скрипт, 12 гибридные (скрипт собирает
доказательства, статус ставит модель), 8 чисто смысловые, 2 справочные — они
существуют, чтобы гасить ложные срабатывания.

Каждое правило несёт норму, статью КоАП, вилку штрафа для юрлица, способ
проверки, подсказку по исправлению и инструкцию ручной проверки на случай,
когда автоматически вывод не получить.

## Как устроено

```
collect.py     сбор фактов        -> artifacts/
registries.py  госреестры         -> кэш
detect.py      детекторы          -> findings.json
смысловой слой квалификация       -> дополненный findings.json
render.py      сборка документов  -> записка + план
```

Разделение содержательное, а не организационное. Скрипт не умеет сказать,
полна ли политика и та ли это организация, чьё название он нашёл в тексте.
Модель не умеет надёжно сравнить два сетевых лога и пересчитать контрольную
сумму ИНН по сотне страниц.

### Три правила, которые важнее удобства

**Статус без доказательства не выставляется.** У каждого пункта записки есть
сетевой запрос, селектор или цитата с сайта. Подтвердить нечем — значит
`UNKNOWN`, а не осторожная формулировка.

**Нехватка данных — не `PASS`.** Реестр не загрузился, страница не открылась —
пункт уходит в «не удалось проверить» с инструкцией, что сделать. Тихое
«нарушений не найдено» по неполным данным — худший отказ этого скилла.

**Происхождение данных едет вместе с выводом.** «Упоминаний иноагентов нет» по
официальному реестру и по зеркалу — утверждения разной силы, и в записке это
различимо.

## Госреестры

Пять реестров: иностранные агенты, экстремистские организации, единый
федеральный список террористических организаций, нежелательные организации,
федеральный список экстремистских материалов.

Реестры живут на `*.gov.ru`, которые отвечают только с российских адресов, —
а Claude из России не работает. Поэтому источник разрешается по цепочке:
официальный сайт → официальный через прокси пользователя → публикуемое зеркало
→ кэш. У пользователя есть выбор: поднять свой прокси с российским выходом
(переменная `PEPPER_RU_REGISTRY_PROXY`) либо использовать зеркало
[`ITSalt/ru-registries-mirror`](https://github.com/ITSalt/ru-registries-mirror),
которое снимается с первоисточника по расписанию с российского VPS.

Архивные снимки реестров в комплект **не входят** намеренно: перечень
иностранных агентов пополняется еженедельно, и устаревшая копия даёт не
«данных нет», а тихое ложное «упоминаний не найдено».

## Что получается на выходе

**`compliance-report.pdf`** (и `.md`, `.html`) — один документ из двух частей.

*Часть I, записка* — резюме, оценка риска в рублях, чек-лист по всем правилам
с нормой, статусом и вилкой штрафа, разбор каждого нарушения с доказательствами
и раздел «что проверить вручную» с конкретной процедурой по каждому пункту.

*Часть II, план* — задачи в порядке убывания риска: что сделать, где именно,
критерий приёмки, ссылка на пункт записки. Задачи, требующие юридического
текста, помечены «нужен вход от заказчика» — без пометки агент-разработчик
напишет политику обработки персональных данных сам, и заказчик получит
документ, который выглядит юридическим, но им не является.

**`remediation-plan.md`** — та же часть II отдельным файлом, чтобы скормить
агенту без норм КоАП и доказательств.

## Чего скилл не делает

Не даёт юридических заключений и не заменяет юриста. Не пишет политику и
согласия — только показывает, чего в них не хватает. Не проверяет содержимое
внешних площадок. Не оценивает отраслевые требования (госорганы, образование,
медицина). Не трогает сайт: только читает.

Два правила штатно остаются без автоматического вывода, и это честная граница,
а не недоработка: единый реестр запрещённой информации (ст. 15.1 ФЗ-149)
машиночитаемо доступен только операторам связи с лицензией и УКЭП, а поиск в
реестре операторов РКН отвечает только с российских адресов. По обоим в записке
печатается инструкция ручной проверки со ссылкой на форму.

## Отказ от ответственности

Скилл выполняет **техническую** проверку сайта и не является юридической
услугой. Статусы, нормы и суммы санкций носят справочный характер, актуальны на
дату проверки и не учитывают отраслевую специфику, судебную практику и
обстоятельства конкретного оператора. Правовую квалификацию даёт юрист.

Автор и ITSalt не несут ответственности за решения, принятые на основании
документов, которые выдаёт скилл, и за последствия таких решений, включая
административные санкции. Программа поставляется «как есть» — см. [MIT](../LICENSE).

## Установка

Подробности — [`anthropic/INSTALL.md`](./anthropic/INSTALL.md).

```bash
cp -R anthropic ~/.claude/skills/pepper-ru-web-compliance
```

Зависимостей нет: всё на стандартной библиотеке Python 3.10+. Playwright
опционален и расширяет покрытие — без него правила про cookie-баннер, состояние
чекбоксов и сетевые запросы уходят в `UNKNOWN`.

## Выбери платформу

| Платформа | Файл |
|-----------|------|
| Anthropic — Claude Code, Claude Desktop, claude.ai | [`anthropic/SKILL.md`](./anthropic/SKILL.md) |
| OpenAI — API / Custom GPT (ручная проверка, без скриптов) | [`openai/system-prompt.md`](./openai/system-prompt.md) |
| OpenAI — ChatGPT Custom Instructions (компактная версия) | [`openai/custom-instructions.md`](./openai/custom-instructions.md) |

Вариант для OpenAI урезан сознательно: без исполнения кода нет ни обхода сайта,
ни сверки с реестрами, поэтому там чек-лист ручной проверки, а не аудит.

## Проверки

```bash
python3 scripts/selftest.py        # регрессии детекторов и матчера, без сети
python3 scripts/gen_checklist.py --check   # чек-лист соответствует rules.yaml
```
