# Государственные реестры

Проверка упоминаний имеет смысл только против актуального реестра. Здесь —
откуда они берутся, что делать при недоступности и как это влияет на выводы.

## Источники

| Реестр | Первоисточник | Доступность |
|--------|---------------|-------------|
| Иностранные агенты | `reestrs.minjust.gov.ru` | Только из РФ; неполная цепочка сертификатов |
| Нежелательные организации | `reestrs.minjust.gov.ru` | То же |
| Экстремистские организации | `minjust.gov.ru` | Глобально |
| Террористические организации | `fsb.ru` | Глобально |
| Экстремистские материалы | `minjust.gov.ru` | Глобально |
| Операторы ПДн | `pd.rkn.gov.ru` | Только из РФ |

## Цепочка разрешения

```
официальный источник напрямую
  -> официальный через прокси пользователя (PEPPER_RU_REGISTRY_PROXY)
  -> зеркало ITSalt/ru-registries-mirror
  -> локальный кэш -> локальный снапшот -> недоступен
```

Каждый результат несёт `origin` (откуда взят) и `source_trust` (какова
юридическая сила). Эти отметки обязаны доезжать до записки.

## Три уровня доверия

**`official`** — первоисточник ведомства, в том числе полученный через прокси
пользователя: прокси это транспорт, а не источник. Позволяет утверждать, что
упоминаний нет.

**`attested`** — зеркало, несущее URL первоисточника, sha256 его исходных байт
и время съёма. Пока съём укладывается в окно свежести (для иноагентов 10 дней,
они пополняются еженедельно), приравнивается к официальному. Просроченный
снимок автоматически понижается до `mirror`.

**`mirror`** — производный источник без цепочки происхождения, например
статья-перечень в Википедии. Данные бывают полны и свежи, но это не официальная
публикация: вывод не поднимается выше `WARN`.

## Если реестр недоступен

Проверить, что именно не отвечает:

```bash
python3 scripts/registries.py probe
```

Три пути, по убыванию предпочтительности:

**Свой прокси с российским выходом.** Даёт официальный источник и полную силу
выводов.

```bash
export PEPPER_RU_REGISTRY_PROXY=http://user:pass@vps:3128
python3 scripts/registries.py update
```

Переменная своя, а не общепринятая `HTTPS_PROXY`, намеренно: прокси применяется
только к загрузке реестров. Обход сайта должен идти напрямую — правила
`PDN-011` и `INF-003` меряют, куда уходят данные форм, и точка наблюдения
меняет результат.

**Зеркало.** Работает само, ничего настраивать не нужно. Уровень `attested`.

**Ручной импорт.** Выгрузить файл со страницы реестра в браузере и подать:

```bash
python3 scripts/registries.py import --registry minjust_foreign_agents \
  --file ~/Downloads/reestr.xlsx --as-snapshot
```

Уровень `official`: источник тот же, изменился только способ доставки.

## Снапшоты не поставляются

Каталог `assets/registries-snapshot/` в релизе пуст, и это осознанно. Архивная
копия реестра в дистрибутиве даёт не «данных нет», а тихое ложное «упоминаний
не найдено» по списку, в котором нужного лица ещё нет. Снапшот создаёт себе
пользователь, если его канал до ведомств нестабилен.

## Неполная цепочка сертификатов

`reestrs.minjust.gov.ru` не присылает промежуточный сертификат, и проверка
падает с «unable to get local issuer certificate». Недостающий сертификат лежит
в `assets/ca/` и цепочка достраивается локально — проверка остаётся включённой.

Отключать проверку сертификата для этих источников нельзя ни при каких
обстоятельствах: реестры служат основанием юридических выводов, и канал, в
котором возможна подмена ответа, обесценивает проверку целиком.
