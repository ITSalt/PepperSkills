## Как работает пакет

Пакет содержит инструкции и локальные скрипты. В режиме managed используется
API временного доступа и потоковый РФ-шлюз; регистрации и отправки отчётов
издателю нет. В режиме custom используется прокси пользователя.
При запуске скриптов данные сохраняются в выбранном пользователем каталоге.
Это могут быть HTML, видимый текст, скриншоты, поля форм, сетевые URL, cookie,
сведения об инфраструктуре, ответы реестров и итоговые отчёты. Сборщик не
отправляет формы с персональными данными, но кликает по кнопкам согласия и отказа.

Локальный браузер обращается через выбранный прокси к проверяемому сайту и
ресурсам, которые тот подключает. Перед аудитом `ipinfo.io` проверяет внешний IP
и его страну через тот же транспорт; провайдер получает технические данные запроса.
Отдельные проверки обращаются к публичным реестрам и источникам сведений об
инфраструктуре; эти получатели видят технические данные запросов, включая IP.
Установка зависимостей обращается к соответствующим репозиториям и CDN.

Состояние отказа сохраняется в `refusal-storage-state.json`: файл может содержать
cookie и localStorage. Он нужен для повторного визита, имеет локальные права
доступа 0600 и не предназначен для публичного распространения.

## РФ-шлюз

Шлюз видит исходный IP соединения, назначения, объёмы и длительности, пересылает
трафик и сам запрашивает фиксированные реестры и DNS/TLS-метаданные. HTTPS сайта
не расшифровывается; незашифрованный HTTP технически доступен прокси. Реестровые
ответы проходят через память сервиса. Серверного браузера и хранения артефактов,
тел HTTP, cookies или пользовательских отчётов нет.

Счётчики запусков и трафика хранятся в SQLite; идентификатор IP — HMAC с постоянным
серверным секретом. Записи удаляются через 48 часов (с очисткой раз в минуту).
Для идемпотентности сохраняется HMAC целевого URL, а не сам URL. Активные сессии
хранятся в памяти. Логи содержат причины отказов, объёмы и длительности; полные
URL, query-параметры и токены не журналируются. Ротация по размеру настроена в
Compose; срок удаления инфраструктурных логов определяет оператор хоста.

Квота привязана к внешнему IP или IPv6 /64, поэтому общий VPN-выход делит лимит.
Собственный прокси пользователя имеет собственные условия обработки данных.

## Клиент с ИИ и передаваемые материалы

Если вы предоставляете артефакты ИИ-клиенту, он обрабатывает их по своим настройкам
и условиям. Пакет не управляет хранением, обучением и сроками удаления данных у
поставщика модели. Перед передачей уберите секреты и лишние персональные данные.

## Хранение и удаление

Локальные артефакты не удаляются автоматически. Их срок хранения определяет
пользователь; для удаления нужно удалить выбранные каталоги артефактов и отчётов.
Резервные копии и история чата управляются отдельно соответствующими системами.

В GitHub Issues сообщения публичны и обрабатываются GitHub по его условиям.
При обращении по электронной почте издатель получает адрес отправителя и текст
обращения для ответа. Не включайте чувствительные сведения. Запросы об удалении
переписки направляйте на контакт выше; удаление публичных данных GitHub также
может потребовать действий в GitHub. Этот текст не устанавливает сроки хранения
у сторонних поставщиков.
