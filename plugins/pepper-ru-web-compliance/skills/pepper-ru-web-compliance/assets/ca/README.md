# Промежуточные сертификаты

Часть ведомственных серверов настроена с неполной цепочкой TLS: отдаёт свой
сертификат, но не присылает промежуточный. Клиент не может достроить путь до
корня и отвергает соединение с ошибкой «unable to get local issuer certificate».

Правильное лечение — положить недостающий промежуточный сертификат рядом и
достроить цепочку локально. Проверка сертификата при этом остаётся включённой.

Отключать проверку (`curl -k`, `verify=False`) для этих источников **нельзя**.
Реестры иностранных агентов и запрещённых организаций — основание для
юридических выводов; канал, в котором возможна подмена ответа, обесценивает
проверку целиком.

| Файл | Кому нужен | Действует до |
|------|-----------|--------------|
| `globalsign-gcc-r3-dv-tls-ca-2020.pem` | `reestrs.minjust.gov.ru` — реестр иноагентов и перечень нежелательных организаций | 18.03.2029 |

SHA-256 отпечаток: `76:25:38:43:95:09:C4:11:C4:37:D3:C5:67:56:3E:13:78:67:12:81:FC:4A:14:64:AD:D0:31:87:08:43:67:6E`

Сертификаты публичные, берутся из поля Authority Information Access серверного
сертификата:

```bash
openssl s_client -connect reestrs.minjust.gov.ru:443 -servername reestrs.minjust.gov.ru </dev/null \
  | openssl x509 -noout -text | grep -A1 "Authority Information Access"
```
