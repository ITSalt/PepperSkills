# Проверка сайта на соответствие требованиям РФ

Собери факты, проверь основания обработки и подготовь записку для владельца
и юриста плюс план для разработчика. Сайт не изменяй.

## Три правила, которые важнее удобства

- **Каждый вывод подтверждён:** запросом, селектором или дословной цитатой.
  Нет доказательства — `UNKNOWN`; неполный сбор не означает `PASS`.
- **Источник указан рядом:** официальный реестр, зеркало или кэш. По
  неподтверждённому зеркалу не повышай вывод выше `WARN`.
- **Наблюдение отдельно от оценки:** машинный `status` сохраняется, смысловая
  проверка записывается в `semantic-review.json`. Это технический аудит;
  окончательную правовую квалификацию даёт юрист.

## Что нужно узнать до запуска

Одним сообщением уточни недостающее: обязательный **URL**, **ИНН владельца**,
если его нет на сайте, и доступный **каталог исходников** для точных мест правки.
Без ИНН проверка уведомления РКН `PDN-010` остаётся неполной.
РФ-шлюз уже настроен в пакете; не проси пользователя задавать его адрес или
менять VPN-клиент. Свой РФ-прокси — необязательный `PEPPER_RU_AUDIT_PROXY`.

## Ход работы

Команды выполняй из каталога установленного скилла. Используй `uv run --no-project`:
зависимости не устанавливаются в проект проверяемого сайта. Нужен `uv`;
инструкции запуска и ограниченного режима — `scripts/README.md`.

### 1. Единый сетевой запуск

```bash
uv run --no-project --with playwright==1.56.0 python -m playwright install chromium
uv run --no-project scripts/audit.py <URL> --out artifacts/ --findings findings.json --max-pages 20
```

Перед запуском зависимости и Chromium проверяются без списания квоты. В режиме
`managed` используется `https://lts.itsalt.ru/ru-audit` без дополнительной настройки.
`PEPPER_RU_GATEWAY_URL` необязательно переопределяет адрес. Для собственного РФ-прокси
пользователь задаёт `PEPPER_RU_AUDIT_PROXY`: API нашего шлюза тогда не используется.
Секреты задаются окружением и не попадают в отчёт. Настройки: `references/gateway.md`.

Одна сессия включает сбор сайта, реестры и РКН. Лимит бесплатного шлюза — три
сетевых запуска за скользящие 24 часа на внешний IP (IPv6 /64), одна активная
сессия на IP, 15 минут, 250 MiB входящего и 10 MiB исходящего трафика. Общий
VPN-IP делит квоту. При отказе покажи код и Retry-After; новую сессию автоматически
не создавай. Повтор потери ответа с тем же ключом не создаёт новый запуск при смене IP.

Playwright, JS, cookies и доказательства остаются локальными; весь сетевой этап
идёт через проверенный российский выход. Прямого fallback нет. Проверяются
отдельные сценарии согласия, отказа и повторного визита; формы не отправляются.
При отказе шлюза сохрани точный код диагностики. Не подменяй managed-сбор
неотмеченным обходом другим инструментом: он не подтверждает сетевой выход.
QUIC и непроксируемый WebRTC отключены — это ограничение наблюдения отражается
в манифесте. Без Chromium допустим явно выбранный `--no-browser`, с `UNKNOWN`
для зависимых проверок. Неполный сбор не означает успешную проверку.

### 2. Реестры

`audit.py` сохраняет результаты в `artifacts/registries/`, включая происхождение,
дату первичного получения, хэш и недоступность. Парсеры прежние. Цепочка:
официальный источник через РФ-выход → зеркало через тот же выход → кэш → снапшот.
Архивные данные не становятся свежими от повторной загрузки.

`registries.py update` и `collect.py` остаются отдельными сетевыми командами;
каждая явно запущенная команда создаёт отдельную сессию. `registries.py status`
и импорт работают офлайн. `PEPPER_RU_REGISTRY_PROXY` — совместимая настройка
только отдельных реестровых команд, она не меняет транспорт сайта.

### 3. Повторная обработка офлайн

```bash
uv run --no-project scripts/audit.py --offline --out artifacts/ --findings findings.json
uv run --no-project scripts/detect.py --artifacts artifacts/ --out findings.json [--inn ИНН]
```

Смысловой анализ и повторная генерация не создают сетевую сессию. Для строго
офлайн-повтора при заданном старом `PEPPER_RU_REGISTRY_PROXY` используй `audit.py
--offline`. Сохрани все правила, включая `LI-001` и `UNKNOWN`; `needs_llm: true`
требует смысловой проверки собранных доказательств.

### 4. Смысловой анализ

Прочитай `references/llm-analysis.md` и `references/semantic-review.md`.
Проверь соответствие политики фактическим формам и трекерам (`PDN-012`),
полноту политики (`PDN-003`), совпадения реестров и маркировки, условия оферты
и применимость пограничных требований. Используй только собранные артефакты.

Не перезаписывай машинный `status`. Сохрани оценку в `semantic-review.json`
с текущим SHA-256 артефактов, источниками и проверяющим; повтори detect.
Для новой оценки заполни итоговое объяснение `summary`; для открытого пункта —
`action` с типом `verify`/`fix`, действием, источниками и содержательной приёмкой.
`fix` допустим только при подтверждённом FAIL и известном месте изменения.
Принятый смысловой PASS закрывает соответствующий пункт в итоговом отчёте,
но не соседние правила. Изменение артефактов требует новой оценки.

### 5. Документы

```bash
uv run --no-project --with playwright==1.56.0 scripts/render.py --findings findings.json --out-dir report/ --format md,html,pdf
```

Без браузера используй `uv run --no-project scripts/render.py --findings
findings.json --out-dir report/ --format md,html`.
Форматы: `references/report-format.md`, `references/remediation-format.md`.
Версия скилла и SHA-256 правил записываются в findings и отчёт. Если генератор
отклонил старые findings, повтори detect; `--allow-legacy` предназначен только
для просмотра старого снимка с явным предупреждением.

### Основание обработки и законный интерес

Для каждого сервиса установи цель, состав данных, получателя, локализацию,
основание и фактический механизм отказа. Домен в HAR подтверждает запрос,
но сам по себе не доказывает нарушение.
POST, расширение `.php` и названия вроде `fields` не доказывают передачу формы
или персональных данных. Используй контекст запроса и подтверждённую связь с
формой. Служебная телеметрия не считается автоматически безопасной.
Для локализации нужны схема потоков, документы и конфигурация баз. Свой домен,
российский бренд, IP сервера и отсутствие сторонних запросов не дают PASS.

Сначала предложи удалить сервис или контейнер, если потребность в нём не
подтверждена. GTM не требуется для соблюдения проверяемых требований РФ:
если используемых тегов нет — удалить. Для остальных решений проверь условия
из `references/not-required-ru.md`, включая требования сервисов и других юрисдикций.

Не имитируй согласие предустановленной галочкой. Для ограниченной аналитики
предложи проверить применимость законного интереса по п. 7 ч. 1 ст. 6 ФЗ-152.
Если необходимость, минимизация, баланс и права субъекта подтверждены,
предложи этот вариант с информированием и работающим возражением/отказом.
Шаблон публичной декларации и варианты интерфейса:
[`references/legitimate-interest.md`](./references/legitimate-interest.md).

Декларация и кнопка отказа сами по себе не дают PASS. Согласие, законный интерес
и обязательная обработка — разные основания; выбор делается отдельно для каждой
цели. При отсутствии подтверждения оставь `UNKNOWN`/`WARN` и один следующий шаг.
Не придумывай факты, настройки или юридические формулировки от имени оператора.

## Что отдаём пользователю

- **`compliance-report.md`, `.html`, при доступном браузере `.pdf`:** часть I —
  резюме, чек-лист, нормы, доказательства и непроверенное; часть II — план правок.
- **`evidence.html`, `evidence.json`:** полный реестр наблюдений с устойчивыми ID;
  в PDF остаются сгруппированные факты и ссылки на реестр.
- **`remediation-plan.md`:** отдельный план для разработчика: действие, место,
  критерий приёмки; необходимые решения владельца/юриста помечены явно.
  P0–P3 относятся к подтверждённым исправлениям; раздел V содержит проверки
  открытых вопросов. Адрес запроса — место наблюдения, а не файл для изменения.

В чате — 3–4 предложения, до 100 слов: результат, главные риски, ограничения и ссылки на файлы.
Находка — одно короткое предложение о факте; объяснение — только если нужно для
решения. Нормы не пересказывай, повторяющиеся правки объединяй. Цитата — минимально
достаточный дословный фрагмент с условиями и исключениями, без жёсткого обрезания.
Полные доказательства сохраняй в артефактах; не дублируй отчёт в чате.
Не складывай штрафы разных правил и не называй такую сумму риском сайта.
Не добавляй поучений «чтобы не ошибаться», «нужно просто», «не переставлять».
Перед выдачей сверь статусы между правилами: заявленное согласие не означает,
что его получение подтверждено; собственный домен не подтверждает локализацию.
Рекомендации должны относиться к обнаруженным сервисам. Исправления в чате
обязательно внеси в findings через смысловую проверку и пересобери файлы.

## Чего скилл не делает

Не изменяет сайт, не выдаёт юридического заключения и не подаёт документы.
Не проверяет внешние площадки и внутренние процессы оператора. Для отраслевых
требований (медицина, образование, госорганы) нужен отдельный профиль.

## Файлы скилла

- `scripts/rules.yaml` — источник правил; `references/checklist.md` и JSON
  генерируются из него. `scripts/signatures.yaml` — сигнатуры детекторов.
- `references/legitimate-interest.md` — обоснование, публичная декларация, интерфейс.
- `references/not-required-ru.md` — когда не внедрять или удалять лишние механизмы.
- Проверка без сети: `uv run --no-project scripts/selftest.py`.

Базовые скрипты используют Python 3.10+ и стандартную библиотеку. Playwright
подключается через `--with playwright==1.56.0`, только когда нужен браузер или PDF.
