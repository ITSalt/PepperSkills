# Проверка сайта на соответствие требованиям РФ

Проверка идёт в четыре слоя, и разделение между ними не организационное, а
содержательное: скрипты фиксируют факты, смысловой слой квалифицирует их.

```
collect.py     сбор фактов        -> artifacts/
registries.py  госреестры         -> кэш
detect.py      детекторы          -> findings.json
смысловой слой квалификация       -> дополненный findings.json
render.py      сборка документов  -> записка + план
```

Скрипт не умеет сказать, полна ли политика обработки данных и та ли это
организация, чью фамилию он нашёл в тексте. Модель не умеет надёжно
пересчитать контрольную сумму ИНН по сотне страниц и сравнить два сетевых
лога. Каждый делает то, в чём не ошибается.

## Три правила, которые важнее удобства

**Статус без доказательства не выставляется.** У каждого пункта записки есть
либо сетевой запрос, либо селектор, либо цитата с сайта. Если подтвердить
нечем — это `UNKNOWN`, а не осторожная формулировка. Записку понесут юристу,
и пункт без основания хуже, чем его отсутствие.

**Нехватка данных — не `PASS`.** Реестр не загрузился, страница не открылась,
рендера не было — значит `UNKNOWN` с указанием, что сделать. Тихое «нарушений
не найдено» по неполным данным — худший отказ этого скилла: владелец сайта
ничего не исправит и получит штраф.

**Происхождение данных едет вместе с выводом.** «Упоминаний иноагентов нет» по
официальному реестру и по зеркалу — утверждения разной силы. В записке это
различимо, и по неофициальному источнику вывод не поднимается выше `WARN`.

Отсюда же дисклеймер, который стоит в начале каждой записки: это техническая
проверка, а не юридическое заключение. Квалификацию даёт юрист.

## Что нужно узнать до запуска

Спросить, если не сказано, — одним вопросом, не анкетой:

- **URL сайта.** Обязательно.
- **ИНН владельца**, если на сайте его нет. Без ИНН правило `PDN-010`
  (уведомление РКН, до 300 тыс. ₽) проверить нечем.
- **Каталог исходников**, если он под рукой. Тогда план для разработчика
  получает точные файлы и строки вместо селекторов.

Не спрашивать про прокси заранее: он нужен, только если реестры недоступны, и
об этом скрипт скажет сам.

## Ход работы

### 1. Сбор

```bash
uv run --no-project --with playwright scripts/collect.py <URL> --out artifacts/ --max-pages 20
```

Главная грузится дважды — до и после нажатия кнопки согласия в cookie-баннере.
Разница между проходами и есть доказательство по правилу `CK-003`.

Если в выводе `режим: degraded`, значит нет Playwright: часть правил станет
`UNKNOWN`. Предложить `pip install playwright && python -m playwright install
chromium`, но не настаивать — проверка работает и так, просто уже.

### 2. Реестры

```bash
python3 scripts/registries.py update
python3 scripts/registries.py status
```

Реестры разрешаются по цепочке: официальный источник → официальный через
прокси пользователя → зеркало → кэш → локальный снапшот. Если в `status`
что-то `unavailable`, сказать об этом прямо и назвать последствие — какие
правила уйдут в `UNKNOWN`. Варианты для пользователя: поднять прокси с
российским выходом (`PEPPER_RU_REGISTRY_PROXY`) либо выгрузить реестр вручную
и подать через `registries.py import`. Подробности — `references/registries.md`.

### 3. Детекторы

```bash
python3 scripts/detect.py --artifacts artifacts/ --out findings.json [--inn ИНН]
```

Выдаёт находки по всем 45 правилам. Статус получает каждое: правило, по
которому наблюдений не собрано, уходит в `UNKNOWN` с причиной, а не исчезает
из отчёта — пропавшая строка читается как «здесь всё в порядке». Часть находок
помечена `needs_llm: true` — это кандидаты, по которым скрипт собрал
доказательства, но квалификацию не даёт.

### 4. Смысловой анализ

Это единственный слой, где работает модель, и работает она строго по
собранным артефактам. Что делать — в `references/llm-analysis.md`; читать
перед тем, как выставлять статусы.

Коротко, по убыванию ценности:

**Сверить декларацию с фактом** (`PDN-012`). Политика обещает одно, а формы и
сетевой лог показывают другое. Это самая результативная проверка скилла:
типовая ошибка — политика из шаблона, не описывающая ни реальные формы, ни
трекеры. Поля форм и список доменов уже лежат в артефактах.

**Проверить полноту политики** (`PDN-003`) по чек-листу ч. 2 ст. 18.1 и ст. 14
152-ФЗ. На каждый подтверждённый пункт — цитата; на каждый отсутствующий —
прямое указание, что его нет.

**Подтвердить или снять совпадения по реестрам** (`DISC-001`, `DISC-003`,
`DISC-006`, `DISC-007`). Скрипт нашёл вхождение строки — модель решает, та ли
это организация и есть ли рядом требуемая плашка нужной формы. Слабые
совпадения снимать не глядя нельзя: «Действие» может быть и обычным словом, и
названием из реестра.

**Квалифицировать пограничное**: реклама это или сведения о собственных
товарах; обмен сообщениями между пользователями или обращение к администрации
(признак ОРИ); информационная продукция или каталог.

**Прочитать оферту** на условия, ничтожные по ст. 16 ЗоЗПП.

Машинный `status` не перезаписывать. Результат смысловой проверки сохраняется
отдельно в `semantic-review.json` в каталоге артефактов, затем повторяется detect.
Формат: `references/semantic-review.md`. Проверяющий указывает источники и
подтверждённое основание каждой пары «сервис / цель». Цитаты должны дословно
находиться в артефактах. Перед браузерным запуском установите Chromium по `scripts/README.md`.

### 5. Документы

```bash
uv run --no-project --with playwright scripts/render.py --findings findings.json --out-dir report/ --format md,html,pdf
```

Получается один документ из двух частей плюс план отдельным файлом. Форматы и
структура — `references/report-format.md` и `references/remediation-format.md`.

### Основание обработки и законный интерес

Для каждого аналитического или рекламного сервиса сначала отдели факт
подключения от правовой квалификации. Домен в HAR доказывает запрос, но не
доказывает нарушение. Установи цель, состав данных, получателя, локализацию,
заявленное основание и фактический механизм отказа.

Для ограниченной аналитики предложи оператору заполнить
[`references/legitimate-interest.md`](./references/legitimate-interest.md). Пункт
7 части 1 статьи 6 ФЗ-152 допустим только при сохранении прав и свобод
субъекта. Декларация без необходимости, минимизации, баланса, информирования и
работающего отказа не даёт `PASS`.

Если тег или контейнер не нужен, первым вариантом предложи удалить его. Для GTM
сформулируй конкретно: контейнер не требуется для соблюдения проверенных
требований; если используемых тегов нет — удалить. Если основание не установлено,
выставь `UNKNOWN` или `WARN` с одним следующим действием, а не придумывай
юридический текст.

## Что отдаём пользователю

**`compliance-report.pdf` (и `.md`, `.html`)** — основной документ.

*Часть I, аналитическая записка* — для владельца сайта и его юриста. Резюме,
оценка риска в рублях, чек-лист по всем правилам с нормой, статусом, вилкой
штрафа для юрлица и ссылкой на расшифровку, раздел «не удалось проверить».

*Часть II, план устранения* — для разработчика. Задачи в порядке убывания
риска, у каждой: что сделать, где именно, критерий приёмки и ссылка на пункт
части I. Задачи, требующие юридического текста или решения владельца, помечены
«нужен вход от заказчика» — без пометки агент напишет политику обработки
персональных данных сам, и заказчик получит документ, который выглядит
юридическим, но им не является.

**`remediation-plan.md`** — та же часть II отдельным файлом, чтобы скормить
агенту-разработчику без норм КоАП и доказательств.

В ответе в чате — три-четыре предложения: сколько нарушений, какие самые
дорогие, где лежат файлы. Не пересказывать записку: её откроют.

## Чего скилл не делает

Не даёт юридических заключений и не заменяет юриста: документы, которые он
выдаёт, — техническая проверка, и ответственность за решения, принятые по ним,
остаётся на получателе. Не проверяет содержимое
внешних площадок — только сайт. Не оценивает отраслевые требования
(госорганы, образование, медицина) — для них нужен отдельный профиль, и об
этом стоит сказать, если сайт очевидно из такой отрасли. Не трогает сайт:
только читает.

## Файлы скилла

| Файл | Назначение |
|------|-----------|
| `references/checklist.md` | Все 45 правил: норма, санкция, способ проверки. Генерируется из `rules.yaml` |
| `references/llm-analysis.md` | Что делает смысловой слой и как оформляет выводы |
| `references/report-format.md` | Структура аналитической записки |
| `references/remediation-format.md` | Формат плана для агента-разработчика |
| `references/registries.md` | Источники реестров, доступность, прокси, ручной импорт |
| `scripts/rules.yaml` | Реестр правил — единственный источник правды |
| `scripts/signatures.yaml` | Данные детекторов: домены, паттерны, юрисдикции |
| `scripts/selftest.py` | Регрессионные проверки скриптов: `python3 scripts/selftest.py`, без сети |

Зависимостей нет: всё на стандартной библиотеке Python 3.10+. Playwright
опционален и расширяет покрытие.
