# Проверка сайта на соответствие требованиям РФ

Найди, что на сайте нарушает требования, и скажи точно: что, где, чем
подтверждено и как исправить. Пользователь запускает скилл, чтобы получить
ответ, а не список того, что проверить самому. Сайт не изменяй.

## Правила вывода

- **Вердикт по каждому пункту.** НАРУШЕНИЕ (FAIL) — однозначные факты;
  РИСК (WARN) — спорная квалификация: позиция из `position` правила, правка и
  условие снятия; ОК; НЕ ПРИМЕНИМО; ВОПРОС ВЛАДЕЛЬЦУ (EXTERNAL) — только то,
  что снаружи сайта не видно (размещение баз, договоры). UNKNOWN — только
  технический сбой сбора, с его причиной.
- **Не отсылай к ручной проверке.** Если факта не хватает, а его можно
  получить из собранных артефактов, реестра или сети, — добудь его сам.
  Формулировки «требует уточнения», «может быть», «проверьте вручную»,
  «назначение не установлено» в итоге недопустимы.
- **Каждый вывод подтверждён** запросом, селектором или дословной цитатой из
  артефактов. Машинный `status` сохраняется, смысловая оценка — отдельно в
  `semantic-review.json`. Технический аудит; дисклеймер о юридическом
  заключении стоит в отчёте один раз.

## Что нужно узнать до запуска

Одним сообщением уточни недостающее: обязательный **URL**, **ИНН владельца**,
если его нет на сайте, и доступный **каталог исходников** для точных мест правки.
РФ-шлюз уже настроен в пакете; не проси пользователя задавать его адрес или
менять VPN-клиент. Свой РФ-прокси — необязательный `PEPPER_RU_AUDIT_PROXY`.

## Ход работы

Команды выполняй из каталога установленного скилла через `uv run --no-project`:
зависимости не ставятся в проект сайта. Ограниченный режим — `scripts/README.md`.

### 1. Единый сетевой запуск

```bash
uv run --no-project --with playwright==1.56.0 python -m playwright install chromium
uv run --no-project scripts/audit.py <URL> --out artifacts/ --findings findings.json --max-pages 20
```

Один запуск: обход страниц, активные сценарии (вход и регистрация, корзина и
оформление заказа, модальные формы — без отправки и без ввода данных),
доразведка (страна, сеть и вендор каждого получателя, принадлежность внешних
аккаунтов бренду, текст документов-файлов, доступность из РФ), реестры и РКН.
Режим `managed` использует `https://lts.itsalt.ru/ru-audit`; настройки —
`references/gateway.md`. Лимит бесплатного шлюза — три сетевых запуска за
скользящие 24 часа на внешний IP, одна сессия, 15 минут, 250 MiB входящего и
10 MiB исходящего трафика. При отказе покажи код и Retry-After; новую сессию
автоматически не создавай. Не подменяй managed-сбор неотмеченным обходом другим
инструментом. Без Chromium допустим явный `--no-browser`: зависимые правила
получат UNKNOWN с причиной.

Если сценарий входа или заказа не дошёл до формы (`manifest.json → scenarios`),
причина видна в отчёте. Повтори запуск с `--max-pages` побольше или открой
ссылку, которую сценарий не нашёл, и сообщи её пользователю одной строкой.

### 2. Повторная обработка офлайн

```bash
uv run --no-project scripts/audit.py --offline --out artifacts/ --findings findings.json
uv run --no-project scripts/detect.py --artifacts artifacts/ --out findings.json [--inn ИНН]
```

Смысловой анализ и генерация не создают сетевую сессию.

### 3. Смысловой проход — обязателен

Прочитай `references/llm-analysis.md` и `references/semantic-review.md`.
Подтверди или исправь каждый пункт с `needs_llm: true` по собранным
артефактам: полнота политики (`PDN-003`), текст согласия (`PDN-008`),
политика против фактических сервисов и полей (`PDN-012`), состав форм
(`PDN-013`), совпадения с реестрами и маркировка, VPN-тексты. Детектор уже
дал поимённый перечень «есть / нет» — проверь каждую строку по тексту и
оставь её или сними с цитатой.

Сохрани оценку в `artifacts/semantic-review.json` с SHA-256 текущих
артефактов и повтори detect. Для нарушения и риска заполни `action.kind: fix`
с конкретной правкой, местом (страница, раздел документа, тег, компонент) и
критерием приёмки. `verify` — только вопрос владельцу по EXTERNAL.
Отчёт без смысловой оценки этих пунктов генератор помечает как **Черновик**;
черновик пользователю как итог не отдавай.

### 4. Документы

```bash
uv run --no-project --with playwright==1.56.0 scripts/render.py --findings findings.json --out-dir report/ --format md,html,pdf
```

Без браузера — `--format md,html`. Форматы: `references/report-format.md`,
`references/remediation-format.md`. Если генератор отклонил старые findings,
повтори detect; `--allow-legacy` — только для просмотра старого снимка.

## Позиция по спорным пунктам

Позиция умеренная и записана в `position` правил: нарушение — при
однозначных фактах, спорное — риск с правкой. Основные случаи:

- **Аналитика без баннера.** Нет баннера, теги аналитики и рекламы грузятся с
  первого визита, а в документах не заявлено ни согласие, ни законный интерес
  — основания нет: НАРУШЕНИЕ (CK-001, CK-003). Заявлен законный интерес — РИСК,
  применимость в LI-001: нужен работающий отказ, после которого теги не
  грузятся ([`references/legitimate-interest.md`](./references/legitimate-interest.md)).
- **Иностранные получатели.** Страна получателя берётся из сигнатуры и
  доразведки. Иностранный трекер без сведений о трансграничной передаче в
  политике — НАРУШЕНИЕ; со сведениями — РИСК (уведомление РКН по ст. 12).
- **Локализация.** Отправка формы на иностранный сервер — НАРУШЕНИЕ;
  иностранные получатели данных посетителей — РИСК; всё российское — вопрос
  владельцу о размещении баз, с перечнем наблюдаемых получателей.
- **Сначала удалить лишнее.** Если сервис или контейнер (GTM без тегов) не
  нужен, первая правка — удалить; условия — `references/not-required-ru.md`.

Не имитируй согласие предустановленной галочкой и не придумывай факты,
настройки или формулировки от имени оператора.

## Что отдаём пользователю

- **`compliance-report.md`, `.html`, `.pdf`:** часть I — нарушения (что, где,
  правка, штраф), риски с позицией, вопросы владельцу, доказательства, все
  пункты; часть II — план P0–P3 с перечнем и критерием приёмки.
- **`remediation-plan.md`:** тот же план отдельным файлом для разработчика.
- **`evidence.html`, `evidence.json`:** полный реестр наблюдений.

В чате — 3–4 предложения, до 100 слов: сколько нарушений и какие главные,
что сделать первым, ссылки на файлы. Не складывай штрафы разных правил.
Не добавляй поучений. Исправления, сделанные в чате, внеси в
`semantic-review.json` и пересобери файлы.

## Чего скилл не делает

Не изменяет сайт, не выдаёт юридического заключения и не подаёт документы.
Не проверяет внутренние процессы оператора. Для отраслевых требований
(медицина, образование, госорганы) нужен отдельный профиль.

## Файлы скилла

- `scripts/rules.yaml` — правила, позиции и правки; `references/checklist.md`
  и JSON генерируются из него. `scripts/signatures.yaml` — сигнатуры,
  псевдонимы сервисов, чек-листы содержания документов.
- `references/legitimate-interest.md` — обоснование, публичная декларация, интерфейс.
- `references/not-required-ru.md` — когда не внедрять или удалять лишние механизмы.
- Проверка без сети: `uv run --no-project scripts/selftest.py` и
  `uv run --no-project scripts/test_verdicts_golden.py`.

Базовые скрипты используют Python 3.10+ и стандартную библиотеку. Playwright
подключается через `--with playwright==1.56.0`, только когда нужен браузер или PDF.
