# Смысловой слой

Детекторы уже вынесли вердикт по каждому пункту и приложили перечень: что
найдено в тексте, чего нет, какие сервисы подключены, какие поля собираются.
Задача смыслового слоя — подтвердить этот вердикт или исправить его по
собранным артефактам. Не ослаблять, не откладывать, не отсылать читателя
«проверить самому».

## Откуда брать данные

Всё уже собрано; на сайт заново не ходить — иначе выводы перестанут
соответствовать зафиксированным доказательствам.

| Что нужно | Где лежит |
|-----------|-----------|
| Текст страницы | `artifacts/pages/<slug>/text.txt` |
| Разметка после рендера | `artifacts/pages/<slug>/dom.html` |
| Формы и их поля, включая модальные окна и оформление заказа | `artifacts/manifest.json` → `pages[].forms`, `pages[].scenario` |
| Итог сценариев входа, заказа, форм | `artifacts/manifest.json` → `scenarios` |
| Сетевые запросы по фазам | `artifacts/network/*.jsonl` |
| Cookie до и после согласия | `artifacts/cookies/*.json` |
| Страна, сеть и вендор получателей | `artifacts/enrich/hosts.json` |
| Внешние ссылки и принадлежность аккаунтов бренду | `artifacts/enrich/links.json` |
| Текст документов-файлов (PDF, DOCX) | `artifacts/enrich/documents/*.txt` |
| Доступность из РФ | `artifacts/enrich/reachability.json` |
| Пункты на подтверждение | `findings.json` → `needs_llm: true` |

## Цитаты

Всё, что попадает в `evidence`, должно дословно находиться в артефактах.
Пересказ, «примерно такая формулировка», склейка из двух мест недопустимы.
Цитата — минимально достаточный фрагмент с условиями и исключениями.

Если детектор написал «в политике нет: порядок уничтожения данных», а ты
нашёл этот раздел под другим названием — сними строку с цитатой найденного
места. Если не нашёл — строка остаётся, и это нарушение.

## Что проверить, по убыванию ценности

### 1. Политика против факта — `PDN-012`

Детектор сверил подключённые сервисы (по сетевому журналу и доразведке) и
поля форм с текстом документов и перечислил то, чего в документах нет.
Проверь каждое имя: сервис может быть назван иначе («Яндекс.Метрика» для
`mc.yandex.ru`, «VK Реклама» для `top-fwz1.mail.ru`). Итог — список
отсутствующих получателей и данных, по нему политику и правят.

### 2. Полнота политики — `PDN-003`

Перечень ч. 2 ст. 18.1 и ст. 14: цели, правовые основания, категории данных
и субъектов, действия, способы, сроки, порядок уничтожения, права субъекта и
порядок отзыва согласия, трансграничная передача, поручение третьим лицам,
cookie, меры защиты. Контакты ответственного проверяет ORG-003. На каждый
пункт — цитата или прямое «нет». Формулировка «раскрыт недостаточно
подробно» бесполезна: по ней нечего исправлять.

### 3. Текст согласия — `PDN-008`

Элементы ч. 4 ст. 9: оператор с адресом, цель, перечень данных, перечень
действий, способы обработки, срок действия, порядок отзыва. Проверяется
текст, на который ведёт подпись чекбокса. Если подпись ведёт только на
политику — отдельного согласия нет, это нарушение.

### 4. Состав форм — `PDN-013`

Сопоставь поля каждой формы (подписка, заявка, вход, заказ) с её назначением.
Паспорт, СНИЛС, дата рождения в форме обратного звонка — лишние данные.

### 5. Совпадения по реестрам

`DISC-001`, `DISC-003`, `DISC-006`, `DISC-007`. Три вопроса подряд:

1. **Та самая организация или лицо?** «Действие», «Возрождение» встречаются в
   тексте сами по себе. Совпадения `[low]` чаще ложные, но снимать их не глядя
   нельзя.
2. **Есть ли рядом требуемое указание?** Смотреть весь материал: плашка может
   стоять в начале статьи.
3. **Соответствует ли указание форме?** Для иноагентов — ПП 2108: русский язык,
   кегль вдвое крупнее основного текста, в начале материала. Сноска со
   звёздочкой в конце форме не соответствует.

### 6. Пограничное

- **Реклама или сведения о своих товарах** (`DISC-008`, `DISC-009`). Каталог и
  цены на своём сайте рекламой не являются. Ссылка на аккаунт на
  заблокированной площадке — риск с правкой «убрать ссылку»; принадлежность
  аккаунта бренду уже установлена доразведкой.
- **Обмен сообщениями между пользователями или обращение к администрации.**
  Первое — признак ОРИ; второе — обычная форма обратной связи.
- **Баннер** (`CK-002`, `CK-007`): отказ на первом экране или спрятан в
  настройках — детектор это уже различил по кнопкам; подтверди по скриншоту.

### 7. Оферта — ст. 16 ЗоЗПП

Условия, ничтожные по закону: договорная подсудность, ограничение
ответственности продавца, невозврат предоплаты, одностороннее изменение цены
после заключения договора, обязательный досудебный порядок.

## Сетевые доказательства

Метод POST, домен и имя обработчика не доказывают отправку формы или состав
данных. `form_relation` с источником `cdp:Page.frameRequestedNavigation`
подтверждает нативную отправку формы. Классы `_candidate` — гипотезы по адресу.
Страна получателя — из сигнатуры вендора или `enrich/hosts.json` (IP, ASN,
RDAP), а не из доменной зоны. Эти ограничения уже учтены в вердиктах
детектора; не понижай из-за них вердикт до UNKNOWN.

## Сила вывода зависит от источника

У находок по реестрам есть поле `source_trust`:

- `official` — первоисточник ведомства. Можно утверждать, что упоминаний нет.
- `attested` — зеркало с подтверждённым происхождением и свежестью.
  Приравнивается к официальному, в записке источник называется.
- `mirror` — неофициальный источник. Вывод не выше `WARN`, формулировка это
  отражает: «по неофициальному источнику упоминаний не найдено».

## Как записать результат

Оценку записать в `artifacts/semantic-review.json` по формату
`semantic-review.md`, затем повторить detect. Для FAIL и WARN — `action.kind:
fix` с правкой, местом и критерием приёмки. Место — то, что правят: раздел
политики, текст согласия, тег в менеджере тегов, компонент формы, шаблон
разметки. Путь к файлу исходников нужен, только если исходники переданы.

## Чего делать нельзя

- Достраивать норму по памяти — нормы и суммы берутся из `rules.yaml`.
- Оценивать то, чего нет в артефактах.
- Смягчать статус, потому что нарушение выглядит мелким.
- Ставить PASS там, где данных не хватило, и UNKNOWN там, где их хватило.
- Писать «требует уточнения», «рекомендуется проверить», «может быть» вместо
  вердикта.

## Краткость

- Резюме находки — одно предложение о факте.
- Обоснование — только различие, влияющее на вывод; норму не пересказывать.
- Одну цитату не повторять для нескольких выводов: дать источник и место.
- Одна правка на пункт; общие правки объединяются с сохранением всех правил.
