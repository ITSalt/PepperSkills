# Формат плана проверки и исправлений

Часть II объединённого документа и отдельный `remediation-plan.md`.
План предназначен для разработчика, владельца и проверяющего.

## Два типа действий

- `fix`: подтверждённый дефект и конкретное исправление. Только эти задачи
  получают приоритеты P0–P3 по потенциальной тяжести подтверждённого нарушения.
- `verify`: открытый вопрос с конкретным шагом проверки. WARN/UNKNOWN всегда
  относятся сюда. Неполная или прежняя смысловая оценка без действия тоже
  требует проверки, даже если она содержит FAIL. Раздел обозначается V.

Общий `fix_hint` не используется как предписание для открытого вопроса.
Машинный FAIL чисто скриптового правила может дать исправление; гибридное
правило требует принятой оценки с конкретным действием и источниками.

## Поля задачи

| Поле | Содержание |
|------|------------|
| Что обнаружено | Принятый смысловой вывод; машинное наблюдение отдельно в части I |
| Где наблюдалось | Страница, селектор, сетевой адрес и сценарий |
| Где менять | Только подтверждённая настройка, интеграция, компонент или файл |
| Что сделать | Проверить недостающий факт либо исправить подтверждённый дефект |
| Критерий приёмки | Проверяемое состояние и подтверждающие материалы |

Сетевой URL не превращается в файл или место правки. Если место изменения
неизвестно, указывается, что компонент ещё нужно определить по доказательствам.
Для юридических решений, локализации и географии получателей явно указывать
ответственного: владелец/юрист.

Сохранение `semantic-review.json` фиксирует оценку, но не доказывает законность.
Для локализации критерий — схема потоков, подтверждение размещения баз и их
конфигурации; оставшиеся неизвестные перечисляются. Для трансграничной передачи
нужна отдельная оценка условий. Машинный PASS не заменяет эту проверку.

Объединять задачи только с одинаковым типом действия, сохраняя все ID правил,
их объяснения, инструкции и приёмку. Нельзя смешивать проверку одного сервиса
с исправлением подтверждённого дефекта другого. Нормы и санкции остаются в
части I; исходная тяжесть нормы не объявляется срочностью неподтверждённой правки.
