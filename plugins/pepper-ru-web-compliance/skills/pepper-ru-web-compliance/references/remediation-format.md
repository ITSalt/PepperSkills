# Формат плана устранения

Часть II объединённого документа; она же выгружается отдельным файлом
`remediation-plan.md`. Исполняет её агент-разработчик, а не человек. Значит: никаких «желательно»,
«рекомендуется рассмотреть» и прочих формулировок, которые нельзя выполнить.

## Свойства задачи

Каждая задача отвечает на четыре вопроса, и все четыре обязательны:

| Вопрос | Как отвечать |
|--------|--------------|
| Что обнаружено | Факт из записки, одной фразой |
| Где менять | Страница и селектор, а в white-box режиме — файл и строка |
| Что сделать | Действие в повелительном наклонении |
| Как проверить | Проверяемый факт, а не намерение |

## Критерий приёмки

Формулируется так, чтобы исполнитель мог проверить себя сам. «Исправить
политику» — не критерий. «Повторный прогон `detect.py` по правилу `PDN-003`
возвращает PASS» — критерий только для чисто машинного правила, способного
его выдать. Для гибридных правил отдельно принимаются свежие технические
доказательства и документированная смысловая оценка (semantic_review).

Где возможно, к машинной проверке добавляется содержательная: «в каждой форме
есть отдельный непредотмеченный чекбокс согласия». Машинная проверка ловит
регресс, содержательная — подмену смысла.

## Порядок задач

По убыванию риска: `P0` критический, `P1` высокий, `P2` средний, `P3` низкий.
Внутри приоритета — по дешевизне устранения.

Не добавлять пояснений о том, почему исполнителю следует соблюдать порядок.

## Задачи, которые разработчик не закрывает один

Часть нарушений требует юридического текста или решения владельца: содержание
политики, формулировка согласия, текст плашки, решение об отказе от трекера.
Такие задачи помечаются «Ответственный за решение: владелец/юрист».
Общее пояснение даётся один раз перед планом.

## Чего в плане быть не должно

Норм КоАП и сумм штрафов — они в части I, а здесь заставляют исполнителя
читать право вместо того, чтобы чинить. Обоснований приоритета длиннее строки.
Задач без места изменения.

Одинаковые исправления группируются в одну задачу с сохранением всех ID правил,
источников и критериев. Название не повторяется в соседнем поле.
Объединённая задача сохраняет действия всех входящих правил. Если исправление
пока не установлено, поле «Что сделать» содержит конкретный шаг проверки.
