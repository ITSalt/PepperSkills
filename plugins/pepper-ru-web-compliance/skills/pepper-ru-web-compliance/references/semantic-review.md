# Отдельная смысловая проверка

`status` — машинное наблюдение. Оно не превращается в юридический PASS после
обнаружения фразы в политике. `processing_activities` разделяет сервисы и цели;
`declared_basis` — кандидат из текста, `verified_basis` изначально отсутствует.
Отрицания, конфликтующие основания и смешанные цели оставляют UNKNOWN.

После проверки документов и настроек сохраните `semantic-review.json` в каталоге
артефактов. `target` и `artifacts_sha256` скопируйте из findings текущего прогона.
Затем повторите detect. Любое изменение исходных JSON/JSONL/HTML/TXT отменит
привязку оценки. Не сохраняйте findings внутри каталога исходных артефактов.

```json
{
  "target": "https://example.ru",
  "artifacts_sha256": "SHA256_FROM_FINDINGS",
  "rules": {
    "LI-001": {
      "status": "PASS",
      "reviewer": "Имя проверяющего",
      "reviewed_at": "2026-09-21",
      "evidence": ["Адрес документа и цитата; артефакты отказа и повторного визита"],
      "activities": [{
        "service": "Точное имя из processing_activities",
        "purpose": "analytics",
        "verified_basis": "Подтверждённое применимое основание",
        "evidence": ["Источник проверки цели, необходимости, минимизации и баланса"]
      }]
    }
  }
}
```

Это образец формата, не готовая оценка. Для PASS должны быть подтверждены все
наблюдавшиеся пары «сервис / цель». Аналогично отдельно фиксируются CK-003 и
другие гибридные правила. Файл представляет утверждение названного проверяющего,
не криптографическую подпись и не результат автоматической юридической экспертизы.

## Отображение результата

После повторного detect принятая оценка задаёт итоговый статус пункта в
Markdown, HTML и PDF. Машинный `status` остаётся в findings и показывается
рядом с оценкой, источниками и проверяющим. PASS/NA убирает только проверенный
пункт из незавершённых правок; UNKNOWN остаётся в разделе непроверенного,
FAIL — в нарушениях. Соседние правила той же группы сами не закрываются.
Старый отчёт — снимок: для нового состояния сайта повторить сбор и detect.

## Краткая запись

Каждый элемент `evidence` содержит источник/место и минимально достаточную
цитату либо ссылку на технический артефакт. Не пересказывать норму и не
дублировать общую методику. Сохранять условия и исключения цитаты, даже если
нужно больше одного предложения. Для каждой пары «сервис / цель» приводить
собственное подтверждение; компактность не отменяет полноту охвата.
