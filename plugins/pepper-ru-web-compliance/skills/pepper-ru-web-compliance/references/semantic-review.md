# Смысловая оценка

`status` в findings — машинный вердикт детектора. Смысловая оценка
подтверждает или исправляет его по артефактам и хранится отдельно, в
`semantic-review.json`: машинный вердикт остаётся виден рядом.
`processing_activities` разделяет сервисы и цели; `declared_basis` — основание,
найденное в тексте документа.

После проверки сохраните `semantic-review.json` в каталоге артефактов.
`target` и `artifacts_sha256` скопируйте из findings текущего прогона и
повторите detect. Любое изменение исходных JSON/JSONL/HTML/TXT отменит
привязку оценки. Findings не сохраняйте внутри каталога артефактов.

Допустимые статусы: `FAIL`, `WARN`, `PASS`, `NA`, `EXTERNAL`, `UNKNOWN`.
`UNKNOWN` — только при техническом пробеле в артефактах; назовите его.

```json
{
  "target": "https://example.ru",
  "artifacts_sha256": "SHA256_FROM_FINDINGS",
  "rules": {
    "LI-001": {
      "status": "PASS",
      "summary": "Основание и условия обработки подтверждены для перечисленных сервисов и целей.",
      "reviewer": "Имя проверяющего",
      "reviewed_at": "2026-09-30",
      "evidence": ["Адрес документа и цитата; артефакты отказа и повторного визита"],
      "activities": [{
        "service": "Точное имя из processing_activities",
        "purpose": "analytics",
        "verified_basis": "Подтверждённое применимое основание",
        "evidence": ["Источник проверки цели, необходимости, минимизации и баланса"]
      }]
    }
  }
}
```

Это образец формата, не готовая оценка. Для PASS должны быть подтверждены все
наблюдавшиеся пары «сервис / цель». Файл — утверждение названного проверяющего,
не криптографическая подпись.

## Отображение результата

После повторного detect оценка задаёт итоговый статус пункта в Markdown, HTML
и PDF; машинный вердикт показывается рядом с оценкой, источниками и
проверяющим. FAIL и WARN попадают в план, EXTERNAL — в вопросы владельцу.
Соседние правила той же группы оценка не закрывает.

## Краткая запись

Каждый элемент `evidence` содержит источник/место и минимально достаточную
цитату либо ссылку на технический артефакт. Не пересказывать норму и не
дублировать общую методику. Сохранять условия и исключения цитаты, даже если
нужно больше одного предложения. Для каждой пары «сервис / цель» приводить
собственное подтверждение; компактность не отменяет полноту охвата.

## Итоговое объяснение и действие

Новая оценка содержит `summary` — одно предложение о факте, которое
отображается как итог пункта. Для FAIL и WARN добавьте `action`:

```json
{
  "status": "FAIL",
  "summary": "В политике нет порядка уничтожения данных и сведений о трансграничной передаче.",
  "reviewer": "Имя проверяющего",
  "reviewed_at": "2026-09-30",
  "evidence": ["pages/documents_privacy-policy/text.txt — разделы 1–9, слов «уничтож» и «трансграничн» нет"],
  "action": {
    "kind": "fix",
    "text": "Добавить в политику раздел о сроках и порядке уничтожения данных и раздел о трансграничной передаче (или прямое указание, что она не ведётся).",
    "evidence": ["pages/documents_privacy-policy/text.txt — разделы 1–9, слов «уничтож» и «трансграничн» нет"],
    "acceptance": "В политике есть оба раздела; повторный аудит даёт по PDN-003 статус ОК.",
    "locations": ["/documents/privacy-policy — разделы 5 и 9"]
  }
}
```

Это пример формата, не готовое заключение. `action.evidence` — непустой список
источников из `evidence` этой оценки. `kind: fix` допустим при FAIL и WARN и
требует непустых `locations`: страница и раздел документа, тег в менеджере
тегов, компонент формы, шаблон разметки или файл исходников. `kind: verify` —
только для EXTERNAL: вопрос владельцу о том, что снаружи не видно. Для PASS и
NA действие не задаётся. Частично заполненный формат отклоняется.

Прежние оценки без `summary` и `action` читаются как совместимые снимки:
показываются итоговый статус и основания, правка берётся из правила.
