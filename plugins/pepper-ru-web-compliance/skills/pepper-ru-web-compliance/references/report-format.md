# Формат аналитической записки

Часть I объединённого документа. Собирает `scripts/render.py` из
`findings.json`. Здесь — требования к содержанию, которое кладёт туда
смысловой слой.

## Кто читатель

Владелец сайта и его юрист. Первый хочет понять масштаб и стоимость проблемы,
второй — проверить обоснованность каждого пункта. Отсюда два свойства: сверху
резюме с деньгами, ниже — доказательства, которые можно перепроверить.

## Структура

1. **Шапка** — ресурс, дата, число проанализированных страниц.
2. **Дисклеймер** — техническая проверка, не юридическое заключение.
3. **Резюме** — количества по статусам, верхняя граница санкций, предупреждение
   об ограниченном режиме сбора, если он был.
4. **Первоочередное** — до пяти самых дорогих нарушений.
5. **Чек-лист** — таблица по группам правил: все правила, включая соблюдённые.
   Колонки: правило со ссылкой на расшифровку, норма, статус, вилка штрафа для
   юрлица, что обнаружено. Санкция за повторное нарушение в колонку не идёт —
   она применима не всегда и завышала бы картину.
6. **Подробно** — по каждому нарушению: норма, ответственность, что обнаружено,
   доказательства, источник данных, как устранить.
7. **Не удалось проверить** — отдельным разделом, с причиной и действием.
8. **Источники данных о реестрах** — откуда взяты, сколько записей, возраст.

## Требования к формулировкам

**Что обнаружено — факт, а не оценка.** «Форм без чекбокса согласия: 6 из 6» —
факт. «Работа с согласиями организована неудовлетворительно» — оценка, по
которой нечего исправлять.

**Доказательство рядом с утверждением.** Не в приложении, не ссылкой на номер
— тут же, под пунктом. Юрист не должен искать.

**Суммы санкций — из `rules.yaml`.** Не по памяти. Оборотные штрафы не
пересчитываются в рубли: они зависят от выручки, и придуманная цифра занижает
риск молча.

**Раздел «не удалось проверить» обязателен,** даже если он пуст. Его отсутствие
создаёт впечатление полного охвата.

## Чего в записке быть не должно

Задач для разработчика — для них часть II. Предположений без
доказательств. Общих рассуждений о важности комплаенса. Рекомендаций
обратиться к юристу в каждом пункте — это сказано один раз в дисклеймере.

Итоговые статусы учитывают принятую смысловую проверку текущих артефактов;
машинное наблюдение остаётся видимым рядом. Закрытые PASS/NA не входят в
незавершённые правки. Полные цитаты не сокращать так, чтобы потерять условия.
