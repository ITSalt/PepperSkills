# РФ-шлюз: развёртывание и нагрузка, 28 сентября 2026

Шлюз 2.3.0 развёрнут на принадлежащем пользователю VPS `77.247.243.9`.
Рабочий адрес: **https://lts.itsalt.ru:8443**; healthcheck:
https://lts.itsalt.ru:8443/healthz. Состояние после проверок — `healthy`.
Российский выход подтверждён независимым запросом через HTTPS CONNECT с другого
VPS: IP `77.247.243.9`, `country=RU` по IPinfo. Это подтверждение маршрута,
а не приёмка доступности реестров или полноты браузерного аудита.

## Для самостоятельной приёмки

В пересобранных пакетах 2.3.0 адрес уже задан по умолчанию: ручная настройка не
нужна. Для старой сборки или явного переопределения адреса можно задать:

```sh
export PEPPER_RU_GATEWAY_URL='https://lts.itsalt.ru:8443'
```

В `audit.py` явно выберите `--mode managed`, если раньше задавали свой
`PEPPER_RU_AUDIT_PROXY`. Команда из корня репозитория после установки зависимостей
и Chromium (замените URL своим):

```sh
python3 plugins/pepper-ru-web-compliance/skills/pepper-ru-web-compliance/scripts/audit.py \
  'https://example.com' --mode managed --out ./artifacts-acceptance \
  --findings ./findings-acceptance.json
```

Новый сетевой запуск требует пустого каталога `--out` и расходует одну из трёх
сессий за скользящие 24 часа на IP. `--offline` повторно использует артефакты.
Сессии smoke-проверок создавались с отдельного VPS `82.202.140.54`; нагрузочные
сессии — в отдельной тестовой базе. TLS-проверка включена, сертификат доверенный,
срок текущего сертификата — до 3 декабря 2026. Split tunneling VPN не требуется.

Пакеты клиента остаются в `dist/pepper-ru-web-compliance/2.3.0/`.
Реестры, браузерные сценарии, custom-прокси и работа в выбранной клиентской среде
остаются для самостоятельной приёмки пользователя. Публичный выпуск оформляется отдельно: [запись релиза](../releases/2026-09-28-ru-audit-gateway.md).

## Результат нагрузки

2 vCPU / 3,82 GiB RAM на хосте; шлюзу выделены **1 CPU / 512 MiB / 128 PID**.
Тест использовал тот же итоговый образ, native TLS, SQLite и nftables, отдельную
БД и внутреннюю Docker-сеть без выхода наружу. Тестовый origin — свой fixture
в отдельном namespace. Реальные сайты и реестры нагрузку не получали.

Генератор плавно увеличивал нагрузку до 20 × 32 CONNECT и удерживал её 20 секунд.
Общий прогон — 43,75 s; передано 163,32 MiB, включая HTTP framing. Лимит генератора
— 5 MiB/s полезного потока. Это ограниченный тест, не длительный soak и не
измерение максимальной интернет-пропускной способности сервера.

| Показатель | Итоговый прогон с суточной историей |
|---|---:|
| История SQLite | 86 400 секундных записей перед тестом |
| Активные сессии / пик туннелей | 20 / 640 |
| Ошибки соединений | 0 |
| Скорость на полной нагрузке | 5,02 MiB/s с framing |
| p95 установки TLS CONNECT | 45,55 ms |
| p95 status API | 1,04 ms |
| Отзыв всех сессий и закрытие туннелей | 193,45 ms; осталось 0 |

Ресурсные показатели — периодические Docker stats, не непрерывный аппаратный
профиль. 21-я активная сессия отклонена с `503 server_busy`. Единственные расширенные
квоты стенда — per-IP admission (100 вместо 3 выдач / 1 активной сессии), чтобы
подавать нагрузку с одного генератора. Глобальный лимит 20, 32 соединения,
10/s + burst 20, байтовые лимиты и TTL оставлены штатными. Адрес fixture разрешён
только в изолированной тестовой конфигурации; production запрещает инфраструктуру.

Дополнительно на VPS: 32 медленных клиента закрыты примерно за 5 s, заголовок
64 KiB получил HTTP 431. После снятия нагрузки проверены HTTP 200 у
`lts.itsalt.ru`, `looktwinstudio.ru`, `shhhrk.looktwinstudio.ru`,
`shtolyar.looktwinstudio.ru` (52–59 ms). Соседние контейнеры не перезапускались.

Тестовый проект, его сеть, SQLite volume и копии секретов удалены. Рабочий
SQLite volume сохранён. На сервере оставлен только рабочий шлюз и прежние сервисы.

## Обнаруженные и исправленные дефекты

1. YAML flow sequence неверно разбирал запятые параметров tmpfs. Значение заключено
   в кавычки; фактический Compose start и read-only/rootfs проверены.
2. Docker embedded DNS переписывал порт 53 до nftables и попадал в loopback deny.
   Фильтр перенесён на output priority -110, после conntrack и до DNAT. DNS работает,
   обращения к metadata, самому шлюзу и служебному VPS блокируются независимым
   сетевым фильтром. Непривилегированный процесс не может изменить правила.
   Добавлен регрессионный тест Docker user-defined network.
3. Суточная история SQLite сканировалась на каждый переданный блок: при 86 400
   записях p95 status API вырос до 7716 ms, CPU достиг выделенного ядра. Итог теперь
   кешируется внутри секунды и обновляется после каждой durable записи; при смене
   секунды, откате часов или рестарте пересчитывается. Запись до пересылки сохранена.
   Повторный прогон дал 1,04 ms; тесты подтверждают сумму, рестарт и границу окна.
