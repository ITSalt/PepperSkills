## 1. P1 — все три переносимых манифеста не соответствуют стандарту

Место: [compliance/plugin.json](/Users/maxnikitin/projects/PepperSkills/plugins/pepper-ru-web-compliance/plugin.json:1), аналогично `pepper-creative-mode` и `pepper-prompt-engineer`.

Во всех отсутствует обязательный `$schema`; поля `skills` и `interface` размещены на верхнем уровне. По актуальной спецификации отсутствие обязательного поля делает пакет невалидным; неизвестные поля клиент должен игнорировать. Codex-совместимый манифест не делает корневой манифест корректным. Это блокирует заявленную переносимость, хотя отдельный клиент со старым загрузчиком может принять платформенный адаптер.

**Исправление:** добавить канонический `$schema`, убрать `skills` из переносимого манифеста, перенести OpenAI-представление в `extensions.com.openai`; генерировать совместимые адаптеры из общих метаданных. Проверять официальную схему при сборке всех трёх пакетов.

Источники: [Agent Plugins, раздел 5](https://agent-plugins.org/specification), [упаковка OpenAI](https://developers.openai.com/plugins/build/plugins), [формат Cursor](https://cursor.com/docs/plugins).

## 2. P1 — основание обработки ошибочно определяется для сайта целиком

Место: [detect.py:903](/Users/maxnikitin/projects/PepperSkills/plugins/pepper-ru-web-compliance/skills/pepper-ru-web-compliance/scripts/detect.py:903).

Новая `basis_kwargs()` объединяет документы и ищет несколько подстрок. Не существует связи «сервис → цель → основание», не распознаётся согласие, не учитываются отрицания. Одно найденное упоминание затем используется в разных находках.

Воспроизведено на локальных фикстурах:

| Текст политики | Фактический результат |
|---|---|
| «Аналитика обрабатывается на основании согласия пользователя» | `not_declared` |
| «Пункт 7. Срок действия договора» | `legitimate_interest_declared` |
| «Мы не используем законный интерес как основание» | `legitimate_interest_declared` |
| Законный интерес для защиты от мошенничества, аналитика и реклама по согласию | Для аналитики также выводится законный интерес |

**Исправление:** хранить сведения по сервисам и целям, разделить заявленное и проверенное основание; неоднозначные упоминания оставлять `UNKNOWN`. Подстроки могут находить кандидатов, но не устанавливать связь с аналитикой. Добавить проверки согласия, отрицания, смешанных целей и нерелевантного «пункта 7». Это соответствует разграничению целей и оснований в [статьях 5–6 ФЗ-152](https://mintrud.gov.ru/docs/laws/130).

## 4. P1 — проверка отказа и повторного посещения не реализована

Место: [collect.py:606](/Users/maxnikitin/projects/PepperSkills/plugins/pepper-ru-web-compliance/skills/pepper-ru-web-compliance/scripts/collect.py:606).

Сборщик остался прежним: первое посещение, нажатие согласия, перезагрузка и обход страниц в контексте с согласием. В модернизации ему добавлена только inline metadata. Нет отдельного отказа, сохранённого состояния отказа и повторного посещения с этим состоянием. Детектор также читает только `before_consent`, `after_consent`, `walk`.

Из-за этого новая проверка законного интереса не может подтвердить работающий отказ. Наличие слова «возражение» в документе — единственное дополнительное наблюдение; настройки аналитики и результат отказа не проверяются, вопреки обещанию справочника.

**Исправление:** независимые браузерные сценарии согласия и отказа, повторный визит с сохранённым отказом, отдельные сетевые/cookie-доказательства и явное состояние неуспешного клика. Проверить сайт-фикстуру, у которого кнопка отказа есть, но сбор продолжается.

## 5. P2 — без браузера LI-001 ошибочно становится неприменимым

Место: [detect.py:951](/Users/maxnikitin/projects/PepperSkills/plugins/pepper-ru-web-compliance/skills/pepper-ru-web-compliance/scripts/detect.py:951).

Новый детектор не проверяет `ctx.degraded`. При отсутствии сетевых наблюдений он возвращает `NA`. Воспроизведено: `degraded=True`, пустая сеть → `LI-001=NA`; отсутствие данных подменяет отсутствие аналитики.

**Исправление:** возвращать `UNKNOWN` с причиной при отсутствии браузерных доказательств; `NA` разрешать только при установленной неприменимости. Добавить регрессию degraded-сбора.

## 8. P2 — инструкции uv не обеспечивают браузерный режим

Место: [INSTALL.md:39](/Users/maxnikitin/projects/PepperSkills/plugins/pepper-ru-web-compliance/skills/pepper-ru-web-compliance/INSTALL.md:39), inline metadata в `collect.py` и `render.py`.

Скрипты объявляют `dependencies=[]`; документированные команды не добавляют Playwright. INSTALL отсылает за установкой Playwright/Chromium в README, где команд установки нет. В чистом uv-окружении сбор перейдёт в degraded, PDF будет пропущен. `pip install` в другом окружении не обеспечивает зависимость для inline-скрипта.

**Исправление:** документировать отдельный браузерный запуск с `--with playwright` и установкой Chromium в согласованной среде, оставить stdlib/degraded путь явным. Проверить из чистой среды. В текущем аудите uv отсутствовал в PATH, поэтому вывод основан на коде и [контракте uv](https://docs.astral.sh/uv/guides/scripts/), а не на выполненном uv-прогоне.

## Остальные незакрытые пункты плана

- **Автономность инструкций.** После распаковки compliance `.skill` команда INSTALL использовать `adapters/chat/` ведёт к отсутствующей папке. Она находится за пределами устанавливаемого скилла. У creative-mode ссылка `../README.md` из SKILL.md также не существует. Markdown-ссылки в скобках проходят проверку; эти ссылки записаны как обычный код и такой проверкой не ловятся.
- **Один источник.** Генератор имеется только у чат-промпта prompt-engineer. Платформенные манифесты и два других чат-адаптера остаются отдельными редактируемыми файлами; сборка копирует их без проверки синхронности. В двух скиллах сохранились обращения к Claude как обязательному исполнителю. Версии плагинов `2.0.0` независимы, но их связь с версией skill `2.4.0` у prompt-engineer не объяснена.
- **Компактность.** План по-прежнему формирует отдельную задачу для каждой находки и повторяет название в соседних полях; группировки одинаковых исправлений нет. Редактура сократила несколько общих абзацев, но критерий плана выполнен лишь частично.
- **OpenAI review.** Файл submission-tests содержит 5 положительных и 3 отрицательных описания, но без воспроизводимых фикстур и отдельно определённой формы результата. В репозитории не найден полный комплект карточки с логотипом, support/privacy/terms URL и регионами. Документ о подаче перечисляет подготовку как будущие действия. По [требованиям OpenAI](https://developers.openai.com/plugins/deploy/submission) это ещё не готовый комплект для ревью.
- **Клиентская приёмка.** Установка/обновление/отключение в Codex, Claude Code, Cursor и Pi с фиксацией версий и полный цикл обновления симлинка не подтверждены этим аудитом. Корректный ZIP не заменяет загрузку клиентом. Визуальная приёмка актуального PDF также не выполнена.

По направлениям аудита: **корректность — требует исправления; сопровождаемость и переносимость — частично; производительность — новых существенных проблем в изменённой логике не выявлено; безопасность — новых технических уязвимостей в просмотренном diff не выявлено, но достоверность правовой квалификации требует исправления.** Полный пентест и проверка всех правовых норм за пределами модернизации не проводились.

Рекомендуемый порядок завершения: манифесты и проверка схем → модель оснований/квалификация уведомлений → сценарии отказа → статусы, доказательства и приёмка отчётов → uv и автономные инструкции → клиентская приёмка → комплект OpenAI review.
