## Какие сведения используют плагины

**Creative Mode** использует переданные для задачи темы, варианты, веса и творческие инструкции. **Prompt Engineer** использует описание задачи, примеры, ограничения и черновики промптов. Пакеты этих навыков не включают сервер издателя, который получает такие промпты. Выбранное ИИ-приложение обрабатывает содержание задачи по своим условиям и настройкам.

**Orchestrator** работает с разрешённым рабочим пространством: планами, пакетами работ, состояниями, ссылками на репозитории и pull request, отчётами о проверках. Он может запускать разрешённые локальные инструменты и взаимодействовать с Git, GitHub, ИИ-клиентами и настроенными пользователем средами. Состав передаваемых данных зависит от конкретной операции и настроек проекта. Файлы рабочего пространства могут попадать в коммиты; их доступность определяется видимостью репозитория и настройками доступа.

Orchestrator может подготовить сообщение об ошибке плагина с заменой частных сведений на placeholders. Автоматическая очистка не гарантирует удаления всех чувствительных сведений. Проверьте текст перед отправкой. Публикация в GitHub Issues требует явного разрешения либо заранее разрешённого пользователем режима автоматических отчётов. Публичные Issues и комментарии доступны всем.

**RU Web Compliance** собирает доказательства о сайте в среде исполнения пользователя. Артефакты могут содержать HTML, текст, скриншоты, описания полей форм, сетевые URL, cookie, сведения об инфраструктуре, ответы публичных реестров и отчёты. Сборщик не отправляет формы с персональными данными, но может нажимать кнопки согласия и отказа. Сохранённое состояние отказа может содержать cookie и localStorage и не предназначено для публичного распространения. Проверяйте сайты только в пределах своих полномочий.

## Шлюз RU Web Compliance и другие получатели

По умолчанию managed-режим использует российский HTTPS-шлюз издателя `https://lts.itsalt.ru/ru-audit`. Для пересылки запросов, ограничения квот и диагностики ошибок шлюз обрабатывает исходный IP соединения, назначения, объёмы и длительности. Идентификаторы квот вычисляются через HMAC от IP или IPv6-префикса; для идемпотентности используется HMAC целевого URL. Это псевдонимные идентификаторы, а не обещание анонимности.

Шлюз не расшифровывает HTTPS-трафик проверяемого сайта. Незашифрованный HTTP технически доступен прокси. На шлюзе нет серверного браузера аудита и хранения артефактов, тел HTTP, cookie или пользовательских отчётов. Ответы реестров проходят через память сервиса. Логи приложения содержат причины отказов, объёмы и длительности; полные URL, query-параметры и токены доступа в них не записываются.

Проверяемый сайт и его ресурсы, публичные реестры и источники инфраструктурных сведений получают запросы, необходимые для аудита. Предварительный запрос к `ipinfo.io` проверяет внешний IP и страну через выбранный маршрут. Установка зависимостей обращается к соответствующим репозиториям и CDN. Прокси пользователя имеет собственные условия обработки данных. Подробности — в [описании потоков данных RU Web Compliance](plugins/pepper-ru-web-compliance/submission/privacy.md); имя издателя и условия хранения обращений в настоящей политике имеют приоритет перед более ранними формулировками этого описания.

Для всех плагинов другими получателями могут быть выбранный поставщик ИИ, GitHub и разрешённые пользователем среды и инструменты. Они обрабатывают данные соответствующей операции по своим условиям. Издатель не управляет хранением чатов, настройками обучения моделей, историей репозиториев и резервными копиями этих поставщиков.

## Хранение и удаление

- **Локальные файлы и история Git:** хранятся в среде пользователя до удаления пользователем; автоматического срока удаления со стороны плагинов нет. Удаление файла не удаляет историю Git, историю чата, внешние копии и резервные копии.
- **Счётчики квот шлюза:** удаляются через 48 часов, очистка выполняется раз в минуту. Активные сессии находятся в памяти на время их существования. Конфигурация развёртывания в репозитории задаёт ротацию логов приложения по размеру — до трёх файлов по 10 МБ на контейнер; это не фиксированный календарный срок. Дополнительные логи хоста и инфраструктуры хранятся по правилам оператора хостинга. Вопросы и запросы об удалении данных, которыми управляет издатель, можно направить издателю.
- **Поддержка по электронной почте:** издатель получает адрес отправителя и добровольно предоставленные сведения для ответа и решения вопроса. Переписка по обращению и копии, которыми управляет издатель, удаляются не позднее 30 дней после закрытия обращения. Отдельное хранение у почтового провайдера регулируется его собственными правилами.
- **Публичные GitHub Issues:** остаются публичными до удаления или редактирования средствами GitHub. Закрытие Issue не удаляет его. GitHub может хранить историю и резервные копии по собственным правилам.

Для запроса доступа, исправления или удаления данных, находящихся у издателя, напишите на **mnikitin@itsalt.ru** и укажите достаточно сведений, чтобы найти нужные материалы. Не отправляйте пароли, API-ключи и лишние документы, удостоверяющие личность. Для копий у поставщика ИИ, GitHub или другого сервиса может потребоваться отдельный запрос или действие в этом сервисе.

## Управление данными

Передавайте только необходимые для задачи сведения. Не включайте секреты и лишние персональные данные в промпты, планы, отчёты и публичные Issues. Проверяйте результаты перед публикацией. Используйте разрешения ИИ-приложения для доступа к рабочему пространству, сетевых действий и внешних записей. Можно отклонить операцию или отключить плагин; отключение не удаляет ранее сохранённые данные автоматически.
