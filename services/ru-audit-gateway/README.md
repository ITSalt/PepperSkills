# РФ-шлюз локального аудита, 2.4.0

Новый клиентский API `/v2/` доступен через HTTPS по адресу
`https://lts.itsalt.ru/ru-audit`: обычные ограниченные HTTP-запросы передают
потоки браузера через исходящий прокси агентской среды. Внутренний HTTP-вход
`8080` публикуется только на `127.0.0.1:18443` хоста; nginx перезаписывает
`X-Pepper-Client-IP`, а сервис принимает его только от `TRUSTED_V2_PROXY_IP`.
Старый TLS-вход `8443/v1` сохранён.

Один Go-процесс, SQLite WAL, native TLS HTTP/1.1. Браузер и отчёты остаются у
клиента. Go 1.26 + CGO (`go-sqlite3`). Лицензия проекта MIT.

## Развёртывание (отдельный операционный этап)

Нужен выделенный контейнер на РФ-хосте с Docker Compose и nftables в ядре.
Не используйте host networking, privileged или общий network namespace.
Для старого v1 Docker публикует порт напрямую: IP берётся из TCP-соединения,
XFF игнорируется, TLS заканчивается в Go, ALPN только http/1.1. Для v2 допустим
только отдельный nginx-вход из [deploy/README.md](deploy/README.md): он
перезаписывает IP-заголовок и проксирует на внутренний HTTP-порт.
HTTPS назначения внутри CONNECT
остаётся исходным TLS сайта, без MITM.

1. Назначьте реальный домен, получите сертификат вне контейнера.
2. Создайте отдельный каталог секретов, доступный UID 10001 только для чтения:
   `tls.crt` (полная цепочка), `tls.key`, `hmac`, `registry-ca.pem`.
   В `registry-ca.pem` объедините PEM из канонического
   `plugins/pepper-ru-web-compliance/skills/pepper-ru-web-compliance/assets/ca/`:
   это опубликованные CA для неполной цепочки Минюста, не секрет и не MITM.
   Compose передаёт файл через `EXTRA_CA_FILE`; сверяйте срок и происхождение CA. HMAC — минимум 32 случайных байта
   в hex, например `openssl rand -hex 32`. Секрет постоянный между перезапусками;
   не коммитьте файлы. Смена HMAC сбросит идентичность квот.
3. В локальном `.env` задайте `GATEWAY_SECRETS_DIR` (абсолютный путь),
   `TLS_SERVER_NAME` (домен сертификата), `DENY_CIDRS` (все публичные IP шлюза,
   его egress и служебной инфраструктуры, через запятую). IPv4 `/32`, IPv6 `/128`
   или более широкая служебная сеть. Образ не содержит общего секрета или домена.
4. Из этого каталога: `docker compose config`, `docker compose build`, затем
   `docker compose up -d`. Том `gateway-data` сохраняет SQLite. Не запускайте
   второй экземпляр на том же файле. Не удаляйте том при обновлении.
5. Проверьте health, firewall и исходный IP, затем задайте клиенту реальный
   `PEPPER_RU_GATEWAY_URL=https://…`. Пройдите живую приёмку ниже до публичной выдачи.

Entrypoint под root устанавливает только собственную таблицу nftables в сетевом
namespace контейнера, затем безвозвратно снимает capabilities и переходит на
UID/GID 10001. Приложение не может менять фильтр. Фильтр запрещает private/special,
служебные CIDR и новые исходящие порты кроме TCP 80/443. DNS разрешён лишь
резолверам `/etc/resolv.conf`, на 53 TCP/UDP. Сервер не предоставляет DNS/UDP-прокси
клиентам. Ошибка установки фильтра останавливает контейнер.
Output-фильтр работает с priority -110: после conntrack, но до Docker DNS DNAT,
чтобы проверять исходный DNS-порт 53, а не переписанный loopback-порт резолвера.

Root healthcheck получает только `/healthz` по loopback с проверкой сертификата.
SQLite-том принадлежит UID 10001; каталог секретов и PEM должны быть доступны ему.
При обновлении сертификата замените файлы и перезапустите сервис: текущие сессии
получат `session_lost`. База квот сохраняется. Бэкап SQLite делайте штатным online
backup либо после остановки, учитывая WAL; срок хранения резервных копий не должен
противоречить политике 48 часов. Внешние access-логи не включайте.

## Конфигурация

| Переменная | Значение по умолчанию |
|---|---|
| `LISTEN_ADDR` | `:8443` |
| `INTERNAL_LISTEN_ADDR`, `TRUSTED_V2_PROXY_IP` | `:8080`, обязательный доверенный адрес для выдачи v2 |
| `DATABASE_PATH` | `/data/gateway.sqlite` |
| `TLS_CERT_FILE`, `TLS_KEY_FILE` | `/run/secrets/tls.crt`, `/run/secrets/tls.key` |
| `HMAC_SECRET_FILE` | `/run/secrets/hmac` |
| `DENY_CIDRS` | обязательна |
| `EXTRA_CA_FILE` | необязательная дополнительная цепочка CA для реестров |
| `SESSIONS_PER_DAY`, `ACTIVE_PER_IP`, `ACTIVE_GLOBAL` | 3, 1, 20 |
| `SESSION_SECONDS` | 900 |
| `DOWNLOAD_BYTES`, `UPLOAD_BYTES` | 262144000, 10485760 |
| `GLOBAL_BYTES_24H` | 21474836480 |
| `CONNECTIONS_PER_SESSION` | 32 |
| `CONNECTION_RATE`, `CONNECTION_BURST` | 10, 20 |
| `CONNECT_SECONDS`, `IDLE_SECONDS` | 10, 60 |

Compose ограничивает память 512 MiB, CPU 2, PID 128, корневую ФС read-only,
логи 3 × 10 MiB. Это стартовые параметры для нагрузочной приёмки на конкретном
хосте. Значения приложения передаются через environment Compose при необходимости;
клиент изменить их не может. Дополнительные предохранители: 1024 входящих
соединения до авторизации, 4096 сохранённых статусов в памяти, две одновременные
выдачи реестров (до 20 MiB исходного тела каждая). Реестровые методы учитывают
как полученные данные, так и JSON/base64-ответ; это консервативнее лимита чистого
полезного содержимого. Счётчик трафика записывается перед передачей блока:
при сбое возможен консервативный перерасход счётчика, но не бесплатная передача.
Скользящая сумма SQLite кешируется только внутри одной секунды и увеличивается
после каждого успешного durable INSERT; при смене секунды, откате часов или
перезапуске пересчитывается. Это устраняет сканирование всей суточной истории
на каждом блоке, сохраняя прежние границы квот и запись до передачи.

Развёрнутый экземпляр и нагрузочный стенд описаны в [deploy/README.md](deploy/README.md).

## API

- `POST /v1/sessions`, JSON `{"target":"https://…"}`, заголовок
  `Idempotency-Key` 16–128 ASCII букв/цифр/`_-`. Ответ содержит `credential`,
  `session_id`, `expires_at`, `limits`, остатки и следующую доступность.
- `GET /v1/sessions/current`, `DELETE /v1/sessions/current`:
  `Authorization: Bearer <credential>`. Статус доступен и для прекращённой сессии
  в течение часа после её срока. Новый токен не выдаётся автоматически.
- Proxy: `Proxy-Authorization: Basic base64(<credential>)`; обычные absolute-form
  HTTP-запросы и CONNECT `host:80|443`. HTTPS outer transport обязателен.
- `GET /v1/registries/{id}`: пять ключей из `api.go`. Ответ: base64 тела,
  SHA-256, дата, первоисточник, конечный URL и `source_trust=official`.
- `GET /v1/registries/operators?inn=…`: только 10/12 цифр, фиксированный путь РКН.
- `POST /v1/probe`, JSON `{"host":"…"}`: DNS и TLS 443, публичные адреса.
- `GET /healthz`: без авторизации. Остальные методы требуют сессию.

Сервер не считает запросы внутри CONNECT и не утверждает, что клиент неизменён.
Доступ к произвольным публичным сайтам необходим для iframe/CDN/API; это позволяет
посторонний обмен в пределах лимитов. Суточная IP-квота не защищает от ротации IP.
Нет произвольного fetch API, SOCKS, UDP, CONNECT-UDP или расширения портов.
DNS-кэш не используется: новое соединение — новое разрешение и проверка всех
A/AAAA, затем dial проверенного IP. Redirect реестра также проходит этот путь.

## Проверки

```sh
go test -race ./...
go vet ./...
# Отдельно от офлайн release-check, из корня репозитория:
python plugins/pepper-ru-web-compliance/skills/pepper-ru-web-compliance/scripts/test_gateway_network.py --browser
bash services/ru-audit-gateway/test-firewall.sh
```

Go-тесты используют временную SQLite, инъекцию DNS/dial и локальные origin-серверы;
это не подтверждение доступности РФ-реестров. Python проверяет настоящий TLS bridge
и Chromium с тестовым сертификатом. Производственная проверка сертификатов не
отключается. Офлайн `scripts/check.sh` проверяет политики клиента без сети.

Перед публикацией на реальном РФ-хосте:

- Провести 3 завершённых запуска и 4-й отказ, идемпотентный потерянный ответ,
  общий VPN-IP, IPv6 /64, смену IP и перезапуск с сохранением базы.
- Подать 20 активных сессий и суммарно до 640 соединений, измерить RSS/CPU/IO,
  задержку SQLite, throughput, скорость закрытия при expiry/revoke/byte cap;
  21-я сессия получает 503 без списания. Тестировать поддельные XFF, медленные
  заголовки/тела, большие заголовки и аварийное отключение клиента.
- Проверить сетевой фильтр независимо от прикладной проверки, затем DNS rebinding,
  публичный redirect во внутреннюю сеть и вызовы публичного IP самого шлюза.
- Из-под VPN проверить наблюдаемый РФ-выход браузера и Python, оба экспорта
  reestrs.minjust.gov.ru, РКН по тестовому ИНН, Минюст и ФСБ; сохранять дату,
  статус и хэш, не пользовательские cookie. Неполный результат — UNKNOWN.
- После бесплатной квоты проверить custom-прокси и полный офлайн-повтор.

Факт успешной сборки образа не заменяет эти проверки. Производственное
развёртывание и изменение существующей инфраструктуры не выполняются сборкой пакета.
